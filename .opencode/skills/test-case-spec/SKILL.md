# 测试用例（TC）规范——唯一定义源

**职责边界**：装「测试用例是什么、怎么写、怎么改」；不装测试点规范（见 test-point-spec）、资料清单（见 tdd-quality-check）、核验清单与问题分级（见 self-review-checklist）、分析方法（见 test-analysis-methods）。

## 定义

**测试用例（TC）= 一条含完整执行信息（前置条件、测试数据、操作步骤、预期结果）的可执行验证，一条只验证一个目的。**

- 可执行：执行者无需追问即可照做
- 与 TP 关系：TC 必须且只能关联一个 TP；一个 TP 至少派生一条 TC（1:N）

## 字段规范

| 字段 | 要求 |
|---|---|
| 编号 | `TC-<功能码>-NNN`（功能码来源、序号规则、名称一致性见 test-point-spec「编号通用约定」） |
| 标题 | 「场景 + 预期」，如「金额超单笔限额，交易拒绝并提示」 |
| 关联 TP | 单个 TP 编号，禁止多值 |
| 优先级 | P0 核心主流程 / P1 重要分支与边界 / P2 次要场景 / P3 罕见与健壮性 |
| 前置条件 | 可构造的具体状态（账户、数据、权限）；环境/版本要求（如 SIT、已配置参数）写入此项，不单列字段；禁止「系统正常」类空话 |
| 测试数据 | 具体值或可执行构造方法，金额/字段给到具体数值 |
| 操作步骤 | 操作者视角，动词开头，编号分步，无歧义词 |
| 预期结果 | 可观察、可判定（界面提示/账务变动/响应码/数据落库），多结果分点列出 |
| 用例类型 | 正向 / 反向 / 边界 / 异常 / 流程 |
| 变更状态 | 预留列（模板列序契约的一部分），当前一律留空 |

## 质量标准

- **单一目的**：一个 pass/fail 结论。验证「超限拒绝」的用例不得同时断言手续费计算；预期可有多个观察点（「余额不变+流水生成」），但必须同属一次判定，出现第二种判定即拆分
- **用例类型归类**：边界=取值在分区边缘（恰等于/恰超出）；异常=系统或环境故障（超时/断网/脏数据）；反向=操作者合法但违反业务规则被拒；流程=跨页面/跨系统的多步骤业务旅程；正向=其余正常场景。交叉时按 **边界 > 异常 > 反向 > 流程 > 正向** 取第一个命中（正向兜底）
- **步骤可执行**：含具体入口、输入值、操作对象；无「适当输入」「等一下」
- **预期可判定**：有具体值/文案/状态，可直接判 pass/fail
- **前置与数据分离**：前置是状态，数据是输入
- 覆盖维度来源：等价类/边界值/判定表/场景法等（方法要点见 test-analysis-methods）

## 清单模板（列序为校验契约，禁止调整）

```markdown
# <目标功能> 测试用例清单（状态：草稿 / 质检后 / 已评审）

| 编号 | 标题 | 关联TP | 优先级 | 前置条件 | 测试数据 | 操作步骤 | 预期结果 | 用例类型 | 变更状态 |
|---|---|---|---|---|---|---|---|---|---|

## 覆盖对照表（以已验收 TP 清单为准）
| TP 编号 | 覆盖的 TC 编号 | 未覆盖原因 |
|---|---|---|
（未覆盖项必须显式填写原因，禁止留空；前端/后端等必需资料未通过检查时不得进入用例生成，不得以覆盖豁免代替资料补齐）
```

## 变更规则

- 评审确认后的调整 → 修订对应行并重新质检（经修复循环后重新确认）
- **设计材料变更或此前缺失的必需资料补齐 → 复查受影响资料，受影响 TC 标记失效并重生成、重新质检**；未受影响的已确认基线保留（材料变更协议由流程编排方约定）
- 受控变更（失效/新增/修改），编号只增不改不复用，删除仅标记废弃
- 「变更状态」列是模板列序契约的一部分，当前流程一律留空

## 输入与历史测试用例使用规则

- **输入资料（必需/可选、目录位置、缺失与冲突处理）见 tdd-quality-check「资料输入模型」**，本 skill 不重述；生成测试用例时必须取到：已验收 TP 基线、同一份测试点资料包（PRD 快照、锚点底册、已登记可用的可选资料）、适用时必需的前端设计与后端设计
- 产物写入功能目录 `output/test-case/test-case.md`；具体路径以派发单为准
- **必需的前端/后端设计任一缺失或不可读 → 暂停生成并交流程编排方处理**；不得把缺失的必需设计当可选项
- PRD 与已验收 TP 是需求和范围基线；设计材料不得推翻二者，冲突交流程编排方请用户澄清
- **存量测试用例使用规则**：仅作场景与步骤写法参考，**禁止照抄历史编号与标题**；每条 TC 仍须满足十字段规范并关联本次验收基线的 TP；与 TP 基线、PRD 或本次设计材料冲突时，以后者为准
