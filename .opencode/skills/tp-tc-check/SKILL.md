# TP / TC 核验清单——唯一定义源

TP/TC 定义见 tp-spec / tc-spec，本 skill 只定义核验方法，不复述定义。

## TP 核验（语义核对，逐项执行、只报异常）

1. **证据核对**：逐条核对锚点定位正确、摘录确实支撑该验证目标；「PRD 没写、推出来」的按三要素核对（来源已注明/挂最相关原文/不与明文矛盾）；用户澄清结论（CL 编号）作依据的与澄清内容不矛盾。摘录逐字一致性不再人工核对——validate.sh 机验保证
2. **切分核对**：合并/拆分合规、三违规（太大/太小/耦合）不出现
3. **命名核对**：「验证」+ 对象（PRD 原词）+ 结果方向，无预期细节与步骤
4. **可判定核对**：每条答得出「看什么分过/不过」；答不出记问题（Blocker）
5. **覆盖核对**：以 scope.md 锚点底册为底册逐锚点核对覆盖**实质完整**（不能只因锚点有 TP 就算覆盖）；范围外或不覆盖的须有显式原因。覆盖表↔TP 依据的**双向映射一致性由 validate.sh 机检**，不人工核对留痕
6. **去重**：同一意图重复 TP 记问题（产物级）

## TC 核验（语义核对，逐项执行、只报异常）

1. **字段完备**：十字段逐项非空；变更状态一律留空
2. **溯源完整**：关联 TP 真实存在于已验收清单；TP↔TC 覆盖对照表未覆盖项有显式原因——常规核验通过后所有 TP 均须覆盖，仅用户明确批准的风险决定可豁免（须核对状态文件中的澄清/风险记录，不能仅凭非空原因放行）
3. **比例提醒**：单 TP 派生 TC 超 10 条，留痕说明原因，不硬禁
4. **步骤可执行、预期可判定、单一目的**：按 tc-spec 质量标准核对；混合意图的拆分修复
5. **领域复核**：对照 test-analysis-methods 领域检查单补遗漏（银行：金额精度/幂等/权限；接口：异常码/超时重试）
6. **名称一致**：标题与正文引用的模块/功能名称与底册登记原文逐字一致

## 问题分级与处置方（报告必标）

| 标注 | 取值 | 判定 |
|---|---|---|
| 级别 | Blocker / Major | Blocker = 无依据或无法判定；Major = 可修的形式与粒度问题，或未决问题可能改变范围/拆分/验收结果 |
| 处置方 | 产物级 / 输入·基线级 | 产物级 = 生成者可修，走修复循环；输入·基线级 = PRD 歧义、材料缺口、基线错误——**立即暂停修复循环呈报用户**，禁止在循环内硬编硬造 |

## 修复与复检约定

- 修复只处理问题清单列出的产物级问题及直接影响项；保留无关已验收内容；编号只增不改，删除仅标记废弃
- 每次修复在产物尾部「质检记录」表留痕（一行一条）：

```markdown
## 质检记录
| 轮次 | 问题编号 | 修复动作（一句话） |
|---|---|---|
```

- **修复后自检（FAIL 清零才交回）**：修复落盘后重跑 validate.sh 对应模式，把「修复引入新问题」挡在复检之前
- 复检在原报告追加一小节；**报告瘦身铁律**：已消解问题复核结论一行带过（`问题编号：已消解（核对点+脚本 PASS）`），禁止重贴摘录、行号与修复后全文；问题清单主表只登记未消解问题
- 修复循环上限 3 轮：仍有未解决问题 → 列明双方依据呈报用户裁定

## validate.sh 用法（必跑）

机械校验分层：生成者交稿前跑对应模式并返回退出码与产物 SHA-256；编排者收回时核对退出码、条目数与 SHA-256；核验者对最终产物正式校验并把退出码写入报告。文件未变化时不重复跑同一校验。

```bash
V=".opencode/skills/tp-tc-check/validate.sh"
# TP 清单核验（含编号/字段/锚点引用/底册全覆盖/覆盖表↔TP依据双向映射/摘录逐字机验）
bash "$V" "workspace/runtime_<项目>/file/<bizFunctionId>/<uuid>" test-point
# TC 清单核验（含十字段/TC→TP引用/TP全覆盖含豁免）
bash "$V" "workspace/runtime_<项目>/file/<bizFunctionId>/<uuid>" test-case
# 锚点底册校验（scope.md + 摘录逐字命中快照）
bash "$V" "workspace/runtime_<项目>/file/<bizFunctionId>/<uuid>/scope.md" scope
# 状态文件校验（登记项固定唯一/确认记录格式/CL 编号唯一/指纹格式）
bash "$V" "workspace/runtime_<项目>/file/<bizFunctionId>/<uuid>/state.md" state
# 完备性扫描（一键候选：章节锚点覆盖状态+功能名命中聚合）
bash "$V" "workspace/runtime_<项目>/file/<bizFunctionId>/<uuid>/scope.md" scan
# 摘录程序化提取（先自验命中快照再输出；禁止模型手抄）
bash "$V" "workspace/runtime_<项目>/file/<bizFunctionId>/<uuid>/scope.md" pull "<锚点>"
# PRD 文本快照生成（textutil/pandoc+引号归一+输出 md5；只读，已存在即拒绝）
bash "$V" "workspace/runtime_<项目>/file/<bizFunctionId>" snapshot "<PRD 文件名>"
```

- 目录推导：会话目录（`<uuid>`）内取 scope.md/state.md；功能目录（上一级）取 prd.txt 与 output/ 产物
- 判读：退出码 0 = 通过；非 0 = 有 FAIL，必须修复后重跑，禁止带 FAIL 定稿
- 覆盖豁免：脚本只检查未覆盖原因已填写；是否获用户批准由核验者核对状态文件决定
- `all` 模式仅限人工调试，正式核验禁止使用

### Windows 环境调用规范（照抄执行，禁止反复探路）

- validate.sh 必须保持 LF 行尾（`.gitattributes` 已约束）；报 `$'\r'` 错误时执行一次 `wsl.exe bash -lc "sed -i 's/\r$//' <脚本绝对路径>"` 后重调并报告
- Windows 统一经 WSL 调用，挂载前缀（如 `/mnt/host/d/`）开工探测一次全程复用；传参用正斜杠，禁止反斜杠
- SHA-256 用 `sha256sum`（WSL 内）；`shasum` 是 macOS 命令；临时校验脚本不落盘
