  3. validate-prd.sh 新增 `check_anchor_source`：底册锚点必须命中快照标题编号，或为合法 M-S-P 派生形且 M/S 与快照标题序号一致（一级标题下无二级标题时才允许 S0；快照全文无编号标题时只允许自建编号）；不通过者报「编号在 PRD 快照中不存在」
  4. validate-prd.sh 修复摘录引号壳 bug：`check_snapshot` 与 `pull` 比对前剥 `「」`/`""` 两端壳，TP 依据比对前去除 `「」`

## 记录 8（2026-11-02）：工具调用死循环复盘——Windows 路径喂给 bash + find 无命中无提示

- **触发**：DQCKGM（定期存款购买）新一轮会话（model `qwen-chat-3.8` variant=low）再次卡死：`find '展示在售产品列表'` 同一条命令连续执行 15+ 次，每次返回「Exited with code 1」且**无任何输出**，会话直到被中断。
- **根因**（三个缺陷叠加）：
  1. **路径体系混用**：把 Windows 绝对路径 `D:\Project\test-expert-agent\workspace\runtime_个人存款\file\DQCKGM` 作为脚本入参传给 bash（脚本本体在 `/mnt/host/d/...`），bash 看不见该路径 → 脚本走「用法」分支，只回一行用法说明，**调用方拿不到「路径不可访问」这一有效诊断**，于是原样重试
  2. **find 模式无命中时静默**：`grep | head` 的退出码取自 `head`（恒为 0），`|| printf '(无命中)'` 永远不触发 → 关键词没命中快照时脚本输出空标题且 exit 0，既不报错也不提示
  3. **关键词是模型自造的**：快照原文是「展示可售产品列表」，模型写成「展示在售产品列表」——仍在凭印象写用词，未执行「find 定位 → line 取原文 → 逐字抄录」的纪律；再叠加路径错误，命令必然失败
  4. **无命令级熔断**：提示词只有「质检修复循环 3 轮收敛」的限制，没有「同一条命令失败 N 次必须换法」的约束；且 agent prompt 派发单要求「绝对路径」，与 bash 需要 bash 可见路径之间没有转换说明
- **改动**：
  1. validate-prd.sh：路径不可访问时输出「[FAIL] 路径不可访问 + 入参须为 bash 可见路径（相对仓库根或 /mnt/host/...），不要传 D:\...」，不再只给笼统用法
  2. validate-prd.sh：`find` 无命中时输出「[FAIL] 关键词未命中快照 + 关键词须取自快照原文用词」并 exit 1；命中才输出行号+原文
  3. prd-quality-check SKILL.md 新增「脚本调用规范（Windows 环境）」：bash 入参路径规范、Windows 绝对路径只用于文件读写工具、中文目录名原样传参且不凭印象拼路径、find 关键词纪律、失败熔断（2 次换法 / 3 次报告）
  4. self-review-checklist「Linux 调用规范」同步补路径规范与命令级熔断（产物侧脚本同受影响）
  5. test-manager.md：行动纪律新增第 5 条「失败即换法，禁止原样重试」；工具箱新增路径规范说明；派发单路径要求改为「给两套（bash 可见相对路径 + Windows 绝对路径）」；红线 5 补「工具失败不得原样重试超过 2 次」
- **回放结果**：以 agent 原命令复现——Windows 路径入参 → 输出「用法」+ exit 2（修复后会输出「路径不可访问」及路径规范提示）；正确 WSL 路径 + 错误关键词 → 明确「关键词未命中快照」+ exit 1（修复前为空输出 + exit 0）；正确路径 + 正确关键词 → 输出「140:- **结果**：展示可售产品列表…」可直接抄录。
- **遗留**：脚本只覆盖 bash 可见路径这一种错法；Git Bash 与 WSL 的环境差异、编码（UTF-8/GBK）在中文路径上的表现仍可能产生新错法，靠熔断条款兜底而不是靠穷举修复。
