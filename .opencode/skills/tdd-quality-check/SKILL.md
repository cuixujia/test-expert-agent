# 资料输入模型与用例生成资料检查——唯一定义源

**职责边界**：装「有哪些资料、在哪、必需还是可选、缺失怎么办、资料够不够支持生成用例」；不装产出核验清单与问题分级（见 self-review-checklist）、需求证据规则（见 prd-quality-check）、分析方法（见 test-analysis-methods）。

## 资料输入模型（全流程唯一权威源）

任何环节用到「有哪些资料、在哪、必需还是可选、缺失怎么办」，一律以此节为准，其他 skill 只引用不重述。

### 资料目录与必需性

| 资料 | 位置 | 必需性 | 用途 |
|---|---|---|---|
| 当前业务功能 PRD 原件 | 功能目录 `prd-doc/` | 必需 | 需求依据原文 |
| PRD 文本快照 | 功能目录 `prd.txt` | 必需 | 锚点来源校验与摘录抄写的字符基准（规则见 prd-quality-check） |
| 锚点底册 | 会话目录 `scope.md` | 必需 | 证据底册（结构见 prd-quality-check） |
| 已验收测试点 | 功能目录 `output/test-point/test-point.md` | 生成用例时必需 | 需求与范围基线 |
| 领域知识 | `domain-knowledge/` | 可选 | 补充领域规则与术语 |
| 逆向文档 | `asset-library/reverse-docs/` | 可选 | 参考历史实现路径 |
| 功能知识 | `asset-library/knowledge-docs/` | 可选 | 参考功能级经验 |
| 存量测试点 | `asset-library/test-point/` | 可选 | 覆盖维度与写法参考 |
| 存量测试用例 | `asset-library/test-case/` | 可选 | 场景与步骤写法参考 |
| 前端设计 | `develop-docs/fe-design/` | 适用时必需 | 有界面功能必须有可读材料；无界面功能登记「前端设计不适用」 |
| 后端设计 | `develop-docs/be-design/` | 必需 | 接口、状态、权限、异常、事务、并发/幂等 |
| 数据库设计 | `develop-docs/db-design/` | 可选 | 字段、类型、长度、枚举、默认值、约束 |
| 澄清附件 | 会话目录 `input/` | 按需 | 只用于理解已登记的澄清；作额外依据须先在资料质检报告与派发单登记 |

### 资料可用性判定（三选一，不得混用）

- **未提供**：目录不存在或文件为空 → 标注「未提供」并继续，不登记为问题
- **不可读**：存在但无法解析 → **不得伪记为「未提供」或静默跳过**；须在报告中列出影响并请用户补充、修复或明确同意跳过
- **与 PRD/基线冲突**：以 PRD 与已验收基线为准；若冲突会改变 TP/TC 的范围、拆分或判定 → 按输入问题暂停并请用户澄清，不得自行采信一方

### 按用途的输入组合

- **测试点生成**：必需 = PRD 原件 + 快照 + 锚点底册；可选 = 领域知识、逆向文档、功能知识、存量测试点
- **测试用例生成**：必需 = 已验收测试点 + 同一份测试点资料包（PRD 快照、锚点底册、已登记可用的可选资料）+ 适用时必需的前端设计与后端设计；可选 = 数据库设计、存量测试用例
- **资料检查**：必需 = 已验收测试点 + 待检资料清单；其余按上表判定

### 通用使用规则

- 存量测试点/存量测试用例**仅作参考，不是本次基线**：禁止整批拷贝、禁止照抄历史编号与标题；每条产出仍须独立满足各自 spec 的硬标准
- 必需资料缺失或不可读 → 暂停并请用户澄清/补充；不得当作可选项、不得自动豁免受影响的 TP/TC
- 用户明确要求带风险推进的，走风险二次确认规则并登记风险与影响

## 检查目的与深度

确认已验收测试点及其证据可继续使用，且生成 TC 十字段（定义见 test-case-spec）所需的适用设计资料可用。检查深度 = 支撑 TC 生成，不要求实现级精度；材料未覆盖的登记缺口，不得静默丢弃、不得补造约束。锚点底册规则见 prd-quality-check，资料输入模型见上节。

## 资料范围

| 资料 | 要求 | 检查规则 |
|---|---|---|
| 测试点资料包（PRD/快照/底册/澄清登记） | 继承复用 | 核对版本/指纹与澄清登记；只复查变化项，不重复完整质检 |
| 已验收测试点 | 必需 | 状态为已验收、编号与锚点可追溯、覆盖当前目标功能 |
| 前端设计 | 适用时必需 | 先判适用性：功能含操作界面 → 必须有可读材料（页面入口、交互、校验、提示、兼容性）；纯接口/纯算法等无界面 → 登记「前端设计不适用」继续；判定存疑请用户确认。复核：PRD 明示界面要求却被判不适用时列为问题 |
| 后端设计 | 必需 | 必须有可读材料；检查接口、状态、权限、异常、事务及并发/幂等等约束 |
| 数据库设计 | 可选 | 有则检查字段/类型/长度/枚举/默认值/约束；无则登记「未提供」继续 |
| 存量测试用例 | 可选 | 有则登记供参考；不得复制历史编号、不得取代已验收 TP；无则登记「未提供」继续 |

**硬门槛**：适用性判定为必需的任一设计缺失、不可读，或存在影响用例步骤/数据/预期的未解决问题 → 结论「暂不可生成」，须请用户澄清或补充；不得把必需缺口当可选项，**不得自动豁免受影响 TP，也不得以覆盖豁免代替资料补齐**。用户明确要求带风险推进的，走风险二次确认规则并登记。可选资料缺失标「未提供」继续；存在但不可读不得静默跳过。

## 五维检查（深度 = 支撑 TC 生成）

| 维度 | 必查 |
|---|---|
| 完整性 | 操作入口、字段约束、枚举、错误码、状态定义、异常路径能否从材料获得 |
| 一致性 | 设计材料与 PRD 底册约束匹配；前后端设计接口契约一致 |
| 无二义性 | 歧义是否改变 TC 的步骤、数据或预期 |
| 可测试性 | 预期可观察可判定；测试数据可构造 |
| 可追溯性 | 每条设计约束可定位到文档与位置 |

## 材料专项检查项

| 材料 | 检查项 |
|---|---|
| 前端设计 | 页面元素与入口、交互事件、提示文案、前端校验规则、兼容性说明 |
| 后端设计 | 接口契约、状态机定义、并发与锁、事务边界、批处理时序、错误码表、幂等约定 |
| 数据库设计 | 字段类型/长度/枚举、默认值、主外键与级联约束 |
| 存量测试用例 | 场景与步骤参考；不得复制编号、不得把历史用例当作本次验收依据 |
| 接口文档 | 请求/响应字段约束、错误码表、幂等约定、签名加密规则 |
| 流程图/时序图 | 分支完整性、异常路径、超时处理（不可解析时按 prd-quality-check 降级规则） |

超长文档分页读完，禁止只读首屏；未变化资料复用既有检查结论；用户补充材料后只复查受影响资料，通过后自动进入用例生成。目录与文件清点一律用 Glob 工具一次完成（存在性判断同理），仅需要文件大小/时间戳时才用 shell，禁止用 shell 探测目录结构。

## 问题分级

**级别与处置方的定义见 self-review-checklist**（唯一权威源），本环节只规定判定口径：

- **Blocker**：受影响 TP 的用例无法生成，或预期无法判定
- **Major**：可暂定用例，但缺口可能改变步骤、测试数据或预期结果

## 资料问题处置与衔接

- 资料问题、用户澄清与复查结果记录在 design-check.md；流程编排方在状态文件登记 CL 编号与必要的风险决策
- 必需资料问题解决后**只复查受影响资料**，通过后自动进入用例生成
- 可选资料未提供不阻塞生成；但**每条已验收 TP 仍须被覆盖**，除非经过风险推进规则明确批准并记录
- 前端/后端/数据库设计后续变更时，按材料变更协议只复查受影响的资料与受影响的 TP/TC，未受影响的基线保留

## 报告模板（design-check.md）

```markdown
# <目标功能> 用例生成资料检查报告

## 结论
Blocker: N 项 / Major: N 项
是否可进入用例生成：<是 / 否，原因>

## 材料清单
| 材料类型 | 路径 | 版本/指纹（可取得时） | 必需/可选 | 提供情况 | 可读性与相关性 | 检查范围/结论 |
|---|---|---|---|---|---|---|

## 问题清单
| 问题编号 | 维度 | 材料来源 | 问题描述（现状→差异→影响） | 级别 | 改进建议 |
|---|---|---|---|---|---|

## 处置记录
| 日期 | 问题编号 | 用户处置 | 备注 |
|---|---|---|---|
```

**报告写法**：按 self-review-checklist「表达与报告规范」执行（表达四原则、问题描述句式、报告瘦身铁律）。

## 处置协议

1. **用户补充材料后**：复查受影响问题，更新处置记录与结论；受影响产物按材料变更协议处理
2. **Blocker 未清零**：声明风险 → 用户以「通过 + 阶段名」二次确认 → 风险决策登记状态文件（强确认协议由流程编排方执行）
