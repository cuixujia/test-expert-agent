# 测试用例（TC）规范——唯一定义源

## 定义

**测试用例（TC）= 一条含完整执行信息（前置条件、测试数据、操作步骤、预期结果）的可执行验证，一条只验证一个目的。**

- 可执行：执行者无需追问即可照做
- 与 TP 关系：TC 必须且只能关联一个 TP；一个 TP 至少派生一条 TC（1:N）

## 字段规范

| 字段 | 要求 |
|---|---|
| 编号 | `TC-<功能码>-NNN`，功能码=平台 bizFunctionId；三位序号只增不改不复用 |
| 标题 | 「场景 + 预期」，如「金额超单笔限额，交易拒绝并提示」 |
| 关联 TP | 单个 TP 编号，禁止多值 |
| 优先级 | P0 核心主流程 / P1 重要分支与边界 / P2 次要场景 / P3 罕见与健壮性 |
| 前置条件 | 可构造的具体状态（账户、数据、权限）；环境/版本要求也写入此项；禁止「系统正常」类空话 |
| 测试数据 | 具体值或可执行构造方法，金额/字段给到具体数值 |
| 操作步骤 | 操作者视角，动词开头，编号分步，无歧义词 |
| 预期结果 | 可观察、可判定（界面提示/账务变动/响应码/数据落库），多结果分点 |
| 用例类型 | 正向 / 反向 / 边界 / 异常 / 流程；交叉时按 **边界 > 异常 > 反向 > 流程 > 正向** 取首个命中 |
| 变更状态 | 预留列（模板列序契约的一部分），当前一律留空 |

## 质量标准

- **单一目的**：一个 pass/fail 结论。验证「超限拒绝」的用例不得同时断言手续费计算；预期可有多个观察点（「余额不变+流水生成」），但必须同属一次判定
- **步骤可执行**：含具体入口、输入值、操作对象；无「适当输入」「等一下」
- **预期可判定**：有具体值/文案/状态，可直接判 pass/fail
- **前置与数据分离**：前置是状态，数据是输入
- 覆盖维度来源：等价类/边界值/判定表/场景法等（方法要点见 test-analysis-methods）

## 清单模板（列序为校验契约，禁止调整）

```markdown
# <目标功能> 测试用例清单（状态：草稿 / 质检后 / 已评审）

| 编号 | 标题 | 关联TP | 优先级 | 前置条件 | 测试数据 | 操作步骤 | 预期结果 | 用例类型 | 变更状态 |
|---|---|---|---|---|---|---|---|---|---|

## 覆盖对照表（以已验收 TP 清单为准）
| TP 编号 | 覆盖的 TC 编号 | 未覆盖原因 |
|---|---|---|
（未覆盖项必须显式填写原因，禁止留空）
```

## 变更与历史规则

- 评审通过后即基线：受控变更（失效/新增/修改），编号只增不改不复用；设计材料变更时受影响 TC 标记失效并重生成，未受影响基线保留
- 存量用例仅作场景与步骤写法参考：**禁止照抄历史编号与标题**；与 TP 基线、PRD 或设计材料冲突时，以后者为准
