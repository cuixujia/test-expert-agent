# 用例生成资料检查——唯一定义源

## 检查目的与深度

确认已验收测试点及其证据可继续使用，且生成 TC 十字段（定义见 tc-spec）所需的适用设计资料可用。检查深度 = 支撑 TC 生成，不要求实现级精度；材料未覆盖的登记缺口，不得静默丢弃、不得补造约束。锚点底册规则见 prd-check。

## 资料范围

| 资料 | 要求 | 检查规则 |
|---|---|---|
| PRD 资料包（PRD/快照/底册/澄清登记） | 继承复用 | 核对版本/指纹与澄清登记；只复查变化项，不重复完整质检 |
| 已验收测试点 | 必需 | 状态为已验收、编号与锚点可追溯、覆盖当前目标功能 |
| 前端设计 | 适用时必需 | 由编排者先判适用性：功能含操作界面 → 必须有可读材料（页面入口、交互、校验、提示、兼容性）；纯接口/纯算法等无界面 → 登记「前端设计不适用」继续；判定存疑请用户确认。复核：PRD 明示界面要求却被判不适用时列为问题 |
| 后端设计 | 必需 | 必须有可读材料；检查接口、状态、权限、异常、事务及并发/幂等等约束 |
| 数据库设计 | 可选 | 有则检查字段/类型/长度/枚举/默认值/约束；无则登记「未提供」继续 |
| 存量测试用例 | 可选 | 有则登记供参考；不得复制历史编号、不得取代已验收 TP；无则登记「未提供」继续 |

**硬门槛**：适用性判定为必需的任一设计缺失、不可读，或存在影响用例步骤/数据/预期的未解决问题 → 结论「暂不可生成」，须请用户澄清或补充；不得把必需缺口当可选项，不得自动豁免受影响 TP。用户明确要求带风险推进的，走风险二次确认规则并登记。可选资料缺失标「未提供」继续；存在但不可读不得静默跳过。

## 五维检查（深度 = 支撑 TC 生成）

| 维度 | 必查 |
|---|---|
| 完整性 | 操作入口、字段约束、枚举、错误码、状态定义、异常路径能否从材料获得 |
| 一致性 | 设计材料与 PRD 底册约束匹配；前后端设计接口契约一致 |
| 无二义性 | 歧义是否改变 TC 的步骤、数据或预期 |
| 可测试性 | 预期可观察可判定；测试数据可构造 |
| 可追溯性 | 每条设计约束可定位到文档与位置 |

## 材料专项检查项

| 材料 | 检查项 |
|---|---|
| 前端设计 | 页面元素与入口、交互事件、提示文案、前端校验规则、兼容性说明 |
| 后端设计 | 接口契约、状态机定义、并发与锁、事务边界、批处理时序、错误码表、幂等约定 |
| 数据库设计 | 字段类型/长度/枚举、默认值、主外键与级联约束 |
| 接口文档 | 请求/响应字段约束、错误码表、幂等约定、签名加密规则 |
| 流程图/时序图 | 分支完整性、异常路径、超时处理（不可解析时按 prd-check 降级规则） |

超长文档分页读完，禁止只读首屏；未变化资料复用既有检查结论。

## 问题分级

- **Blocker**：受影响 TP 的 TC 无法生成或预期无法判定
- **Major**：可暂定 TC，但缺口可能改变步骤、测试数据或预期结果

## 报告模板（design-check.md）

```markdown
# <目标功能> 用例生成资料检查报告

## 结论
Blocker: N 项 / Major: N 项
是否可进入用例生成：<是 / 否，原因>

## 材料清单
| 材料类型 | 路径 | 必需/可选 | 提供情况 | 可读性与相关性 | 检查范围/结论 |
|---|---|---|---|---|---|

## 问题清单
| 问题编号 | 维度 | 材料来源 | 问题描述（现状→差异→影响） | 级别 | 改进建议 |
|---|---|---|---|---|---|

## 处置记录
| 日期 | 问题编号 | 用户处置 | 备注 |
|---|---|---|---|
```

报告瘦身铁律见 tp-tc-check：只写结论性发现，不设过程性附录，复查结论一行式。设计资料后续变更时只复查受影响资料与受影响 TP/TC，未受影响基线保留。
