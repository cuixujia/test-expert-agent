# 定期存款购买 锚点底册

## 锚点清单
| 锚点 | 条目摘要 | 原文摘录 |
|---|---|---|
| 3.2 | 功能范围：产品货架展示、产品详情查看、购买信息录入、利息试算展示、业务规则校验、利率锁定与起息、到期处理方式选择、推荐人关联、交易提交与结果反馈、异常场景处理 | 「本任务承接 BRD 第三章 3.1 节定义的功能范围」 |
| 3.3 | 排除项：定期定投、代办购买、大额存单购买、外币定期存款、定期存款支取/提前支取、定期存款查询、营销活动管理、手机银行渠道 | 「每月自动扣款购买定期的签约功能不在本次范围」 |
| 3.4 | 用户范围：已实名认证的个人客户，证件在有效期内；仅个人网银渠道；仅普通定期存款产品 | 「**目标用户**：已实名认证的个人客户，证件在有效期内」 |
| 4.1 | 主流程 E01~E08：进入存款专区、查看产品详情、选择付款账户、输入购买金额、选择存期和到期处理方式、阅读提示并确认、提交交易、返回交易结果 | 「客户通过个人网银购买定期存款的完整流程如下」 |
| 4.2.1 | 余额不足处理 B01：购买金额大于转出账户可用余额时阻止提交，提示缺口金额，引导转入资金或更换付款账户，不提供垫资或透支选项 | 「页面提示"余额不足，还差 XX 元"，告知具体缺口金额」 |
| 4.2.2 | 产品售罄处理 B02：额度用完或停售时列表页显示售罄/暂停销售标签，详情页禁止购买按钮，提交时提示已售罄，并推荐同类在售产品 | 「列表页：产品卡片显示"今日额度已售罄"或"暂停销售"标签」 |
| 4.2.3 | 证件过期处理 B03：客户身份证件已过期时限制线上渠道办理存款购买，提示先更新证件并指引到柜面 | 「提示"您的证件已过期，请先更新证件信息"，限制办理非柜面业务」 |
| 4.2.4 | 系统处理超时处理 B04：核心系统处理超时时禁止引导客户重试，后台核实交易最终状态，确认后主动通知客户，失败则自动解冻/退回已扣划资金 | 「**禁止引导客户重试**，避免重复扣款造成资金损失」 |
| 4.2.5 | 触发限额处理 B05：触达单户上限、单日限额或 II 类户限额时拦截超限购买申请，区分限额类型给出针对性提示，II 类户提示升级 I 类户或降低购买金额 | 「明确提示"已超过 XX 限额，当前剩余额度为 XX 元"，告知是哪一类限额及剩余额度」 |
| 4.3.1 | 利率锁定规则 R01：按购买时银行公示的挂牌利率锁定合约利率，之后银行降息或加息不影响已成交的定期存款，当天买入当天起息 | 「按购买时银行公示的挂牌利率锁定合约利率」 |
| 4.3.2 | 到期日计算规则 R02：到期日 = 起息日 + 存期，存期按月计算，对月对日 | 「到期日 = 起息日 + 存期。例如：2026 年 1 月 31 日存入一年期」 |
| 4.3.3 | 自动转存规则 R03：选择自动转存的存款，到期后按到期日银行挂牌利率续存同期限，转存设置在购买后可以修改 | 「选择自动转存的存款，到期后按到期日银行挂牌利率续存同期限」 |
| 4.3.4 | 合规红线 R04：利率必须锁定、提示必须确认留痕、宣传不能误导、可疑交易不重试、销售可回溯 | 「**利率必须锁定**：客户购买时的利率写入合约，事后不能变更」 |
| 4.3.5 | 起存金额与递增单位规则 R05：购买金额必须达到产品规定的最低起存金额且按递增单位递增，不满足条件的金额不允许提交 | 「定期存款购买金额必须达到产品规定的最低起存金额（如 50 元起）」 |
| 4.3.6 | II 类户限额规则 R06：II 类户购买定期存款受日累计不超过 1 万元、年累计不超过 20 万元约束，超出限额的交易拒绝处理 | 「II 类户购买定期存款受以下限额约束：日累计不超过 1 万元，年累计不超过 20 万元」 |
| 5 | 功能矩阵 F01 定期存款购买：涵盖 10 个子步骤的完整流程处理；待澄清事项包括 II 类户限额校验执行层级、推荐人关联是否强制要求、销售可回溯触发条件、系统超时后核实流程时效 | 「目的：完成个人网银渠道定期存款购买的完整交易流程」 |
| 6.1.1 | F01 定期存款购买业务流程：10 个子步骤、业务规则、业务对象、业务界面、完成标准 | 「本功能涵盖定期存款购买的完整流程，包含以下 10 个子步骤」 |
| 7.1 | 性能要求：产品列表页加载时间≤2 秒、利息试算响应时间≤1 秒、交易提交响应时间≤5 秒、支持至少 1000 用户同时在线浏览和购买 | 「产品列表页加载时间：≤2 秒」 |
| 7.2 | 安全要求：交易前须验证客户实名认证状态和证件有效期、所有交易数据采用 HTTPS 加密传输、所有购买交易须记录完整流水、交易提交前须通过反洗钱黑名单检查 | 「客户身份验证：交易前须验证客户实名认证状态和证件有效期」 |
| 7.3 | 可用性要求：系统可用性≥99.9%、故障恢复 30 分钟内恢复服务、外部系统不可用时明确提示受影响功能 | 「系统可用性：≥99.9%」 |
| 7.4 | 合规要求：严格执行 II 类户限额、单笔交易≥5 万元须向风险控制系统报送大额交易、证件过期客户限制办理线上业务、预留双录/视频回溯接口 | 「II 类户限额：严格执行日累计 1 万元、年累计 20 万元限额」 |
| 7.5 | 审计要求：完整记录每笔交易的请求参数、处理结果、调用链路；记录客户关键操作的时间戳；所有异常场景须记录详细错误信息和堆栈 | 「交易日志：完整记录每笔交易的请求参数、处理结果、调用链路」 |
| 7.6 | 兼容性要求：支持主流浏览器最新版本；个人网银渠道与手机银行渠道参数隔离，互不影响 | 「渠道隔离：个人网银渠道与手机银行渠道参数隔离，互不影响」 |
