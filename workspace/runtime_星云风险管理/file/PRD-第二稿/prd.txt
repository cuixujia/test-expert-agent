2. 背景与依据
2.1 业务背景
依据父级 BRD《业务需求说明书》第 1 章"背景"：当前测试过程中发现的项目风险分散在不同项目页面和人工沟通中，缺少统一的风险登记、审核、跟踪与闭环入口。测试人员上报风险后，测试管理人难以集中审核并推动处理；风险进入"雪狼"平台后的处理结果也无法及时回到"星云"，导致项目日报、首页风险墙及质量看板的数据口径不一致，风险状态和等级缺乏完整展示。
为提升项目风险管理效率，BRD 提出在"啄木鸟"平台新建项目风险管理模块，建立从风险上报、审核、跨平台流转到结果回写和统计展示的业务闭环。本次任务即承接该闭环建设，落地于一体化测试平台（SYS_NEBULA）。

3.2 业务范围
本次任务承接以下四块业务内容（依据 BRD 第 3 章 需求范围 3.1–3.4）：
（一）风险登记（BRD 3.1）
	•	测试人员在一体化测试平台的项目风险管理模块中新增风险。
	•	风险内容、分类、来源、级别、处理人、审核人为必填项；附件为选填项。
	•	提交成功后，风险进入待审核状态，并自动向对应测试管理人发送审核提醒。
（二）风险审核与跨平台流转（BRD 3.2）
	•	测试管理人对处于待审核状态的风险执行通过或拒绝操作。
	•	审核通过后，风险自动推送至"雪狼"平台进入后续处理。
	•	审核拒绝后，风险直接关闭，不可重新提交，也不推送至"雪狼"平台。
	•	"雪狼"端处理后的风险状态、应对措施和实际影响实时回写至"星云"。
	•	定时任务补充同步已关闭风险数据，确保两端风险状态最终一致。
（三）风险列表与检索（BRD 3.3）
	•	提供统一风险列表页，支持查看风险基本信息、当前状态、处理进展和详情。
	•	支持按风险内容、分类、来源、级别、状态、处理人、审核人、创建时间等条件进行高级搜索。
	•	提供"全部、我创建的、待我审核的"快捷筛选："全部"按用户可见权限展示可访问风险；"我创建的"仅展示当前用户创建的风险；"待我审核的"仅展示当前测试管理人需要审核的风险。
（四）关联页面与报表改造（BRD 3.4）
	•	项目日报："今天遇见的问题"自动关联当天有变动的全量风险（含当天已关闭项）；"历史未解决的问题"仅关联此前产生且当前仍未关闭的风险。
	•	项目首页：近三日风险墙保持原有取值规则不变，并在现有展示基础上增加风险解决状态和风险等级字段。
	•	质量看板与二级部看板：接入新的项目上报风险统计数据，保证风险状态、等级和统计口径与新模块一致。
	•	报表查询：新增"项目上报风险记录表"，支持按既有查询条件检索和导出风险记录。

4. 业务流程总览
本章基于父级 BRD 第 4 章"业务流程"和本 PRD 第 3 章已确认承接范围，描述一体化测试平台（SYS_NEBULA）在项目风险管理闭环中的三类主流程：风险上报与审核、雪狼处理与结果回写、风险查询跟踪与统计。本章仅覆盖第四章授权范围，不生成第五章功能矩阵及以后章节，也不展开"雪狼"平台内部页面、流程和实现设计。
4.1 风险上报与审核流程
参与角色：测试人员、测试管理人；系统自动完成必填校验、状态变更和审核提醒发送。
触发事件：测试人员在项目风险管理菜单发起"新增风险"。
前置条件：测试人员可访问一体化测试平台（SYS_NEBULA）的项目风险管理模块；风险表单字段字典（分类、来源、级别等）可用；目标审核人具备测试管理人身份或对应审核职责。
输入：风险内容、风险分类、风险来源、风险级别、处理人、审核人（均必填），附件（选填）。
输出：待审核风险记录；发送给指定测试管理人的审核提醒；审核结论；审核通过后的推送指令或审核拒绝后的关闭终态。

4.2 雪狼处理与结果回写流程
参与角色："雪狼"平台（外部上游系统）、一体化测试平台（SYS_NEBULA）定时任务与数据汇聚能力。
触发事件：本系统将审核通过的风险推送至"雪狼"平台后，"雪狼"端开始处理。
前置条件：风险在本系统中已完成审核通过并成功推送；两端存在可用于关联同一风险的业务标识或接口约定（具体接口字段在依赖登记中另行细化）。
输入："雪狼"端更新的风险处理状态、应对措施、实际影响；"雪狼"端关闭风险后的关闭状态及最终处理信息。
输出：写入本系统的风险处理进展数据；用于风险列表、详情页、项目日报、首页近三日风险墙、质量看板、二级部看板和报表查询的最新风险状态与等级。

4.3 风险查询、跟踪与统计流程
参与角色：风险列表用户（含测试人员、测试管理人及其他有权限用户）、系统取数与展示组件。
触发事件：用户进入风险列表页、切换快捷筛选、组合高级搜索条件，或关联页面/报表按既定口径读取风险数据。
前置条件：用户具备对应风险可见权限；风险数据已由登记、审核、回写或补同步流程更新至本系统；项目日报、项目首页、质量看板、二级部看板、报表查询具备读取新风险统计数据的接入能力。
输入：当前用户身份与权限；快捷筛选项（全部/我创建的/待我审核的）；高级搜索条件（风险内容、分类、来源、级别、状态、处理人、审核人、创建时间等）；关联页面的取数口径。
输出：按权限和条件返回的风险列表；风险详情与处理进展；项目日报"今天遇见的问题"和"历史未解决的问题"；项目首页近三日风险墙增加解决状态和等级字段；质量看板/二级部看板的统一口径统计数据；"项目上报风险记录表"检索与导出结果。

关键业务规则：
	•	风险列表默认使用"全部"视图，并按用户可见权限过滤（GOAL-03）。
	•	"我创建的"仅展示当前用户创建的风险；"待我审核的"仅展示当前测试管理人需要审核的风险（GOAL-03）。
	•	高级搜索支持多条件组合，条件维度以 BRD 3.3 列明为准（GOAL-03）。
	•	项目日报两类问题区分别采用"当天有变动全量风险（含已关闭）"和"此前产生且当前仍未关闭"两个独立口径（GOAL-06）。
	•	项目首页近三日风险墙沿用原取值规则，不得因本次改造改变原有范围，仅新增解决状态和等级展示（GOAL-06）。
	•	所有关联页面和报表须使用统一的风险状态、等级与统计口径，避免再次出现分散不一致问题（GOAL-06）。
与其他系统的边界：本流程主要发生在一体化测试平台（SYS_NEBULA）内部，数据来源包括本系统登记审核数据和"雪狼"回写/补同步数据；"雪狼"仅作为上游数据提供方，不承担本项目关联页面展示职责。

风险管理
模块编号：MOD-01 模块边界：以项目风险对象的全生命周期为同一业务对象和管理目标，覆盖新增登记、列表展示、审核、编辑、复制、删除、导出、消息提醒和权限控制；完成结果是风险从登记到审核决策的闭环管理。
新增风险
功能编号：FUNC-01（变化类型：新增）
业务流程
	•	测试人员进入一体化测试平台（SYS_NEBULA）项目风险管理模块，点击"新增风险"发起登记（触发事件）。
	•	在风险表单中填写六项必填信息：风险内容、风险分类、风险来源、风险级别、处理人、审核人；按需上传附件（选填）。
	•	系统对必填项执行完整性校验：缺失时提示具体缺失字段并阻止提交，用户补充后重新提交。
	•	校验通过后系统保存风险记录，初始状态置为"待审核"，记录创建人、创建时间。
	•	保存成功事件自动触发 FUNC-08 消息提醒，向指定测试管理人发送审核提醒。
业务规则
	•	BR-RISK-01 必填约束：风险内容、分类、来源、级别、处理人、审核人均必填，任一缺失不允许提交；附件为选填项（GOAL-01 / BRD 3.1）。
	•	BR-RISK-02 初始状态：提交成功后风险状态唯一为"待审核"，不可直接进入其他状态。
	•	BR-RISK-03 入口收敛：本功能仅提供项目风险管理模块内的统一新增入口；不新增工作台"审核"tab，也不汇总冒烟等其他待审核事项（EXCL-01）。
	•	BR-RISK-04 字典依赖：分类、来源、级别等字段取值来自系统维护的字典，字典为空或不可用时应阻止提交并提示，不得由前端硬编码兜底。

列表展示
功能编号：FUNC-02（变化类型：新增）
业务流程
	•	用户进入项目风险管理模块的风险列表页。
	•	默认加载"全部"视图：按当前用户的可见权限返回可访问的风险记录，分页展示。
	•	用户可切换快捷筛选："我创建的"（仅当前登录用户作为创建人的风险）、"待我审核的"（当前测试管理人需审核的待审核风险）。
	•	在任一视图下，用户可组合高级搜索条件进一步缩小范围：风险内容（模糊）、分类、来源、级别、状态、处理人、审核人、创建时间区间。
	•	点击列表中某条风险进入详情页，查看基本信息、当前状态、处理进展（含雪狼回写的处理状态、应对措施、实际影响）。
	•	列表数据始终反映 FUNC-01 登记、FUNC-03 审核（含自动联动推送）、FUNC-10 回写、FUNC-11 补同步后的最新状态。
业务规则
	•	BR-LIST-01 默认视图："全部"视图是默认入口，必须按用户可见权限过滤，不可越权看到无权限风险（权限判定见 FUNC-09）。
	•	BR-LIST-02 快捷筛选语义："我创建的"以创建人字段=当前用户为准；"待我审核的"以审核人字段=当前用户且状态为"待审核"为准；两者可与高级搜索叠加。
	•	BR-LIST-03 高级搜索维度固定集：风险内容、分类、来源、级别、状态、处理人、审核人、创建时间共八项，不得随意增减核心维度。
	•	BR-LIST-04 数据新鲜度：列表展示的状态、处理进展等字段必须来自本系统最新落库值（含回写和补同步），不允许缓存导致明显过期。
	•	BR-LIST-05 只读约束：本功能仅负责查询、筛选和详情展示，不提供修改风险主数据的操作入口；编辑/复制/删除分别在 FUNC-04/FUNC-05/FUNC-06 定义。
	•	BR-LIST-06 详情完整性：详情页必须展示六项必填信息 + 附件 + 当前状态 + 处理进展（处理状态、应对措施、实际影响）+ 关键时间戳。

审核风险
功能编号：FUNC-03（变化类型：新增）
业务流程
	•	测试管理人进入待审核风险列表或从 FUNC-08 提醒入口打开风险详情。
	•	核对风险信息（内容、分类、来源、级别、处理人、附件），判断是否符合承接条件。
	•	执行审核结论：通过（该风险应进入后续处理链路）或拒绝（该风险不应纳入正式闭环处理）。
	•	系统按结论变更风险状态：通过 → "已审核/待同步"，并在本功能内自动联动推送至雪狼平台；拒绝 → "已关闭（审核拒绝）"，流程终止，不推送雪狼。
	•	审核通过时，系统组装推送数据包（风险唯一标识、风险内容摘要、分类、来源、级别、处理人、审核人、创建时间、审核时间、审核结论、附件引用地址如雪狼侧需要、项目/业务归属标识如有），调用与"雪狼"平台约定的接口/消息通道发出推送指令。
	•	收到雪狼受理回执后，将本地风险的"推送状态"标记为已推送，记录推送时间与回执标识。
	•	记录审核人、审核时间、审核结论及推送回执信息，用于审计与统计。
业务规则
	•	BR-AUDIT-01 状态约束：仅"待审核"状态的风险可被审核；其他状态不展示审核操作入口。
	•	BR-AUDIT-02 双分支互斥：每条风险只能产生一次有效审核结论，通过后不可再改为拒绝，拒绝后不可重提也不可再审核。
	•	BR-AUDIT-03 通过后果与自动推送：审核通过必须在本功能内自动联动推送至雪狼平台，不允许存在"已通过但未推送"的中间人工步骤；一条风险只推送一次。
	•	BR-AUDIT-04 拒绝后果：审核拒绝直接关闭，不推送雪狼，不进入任何后续处理链路（GOAL-02 / EXCL-03）。
	•	BR-AUDIT-05 权限约束：只有具备测试管理人身份或对应审核职责的用户可执行审核（见 FUNC-09）。
	•	BR-AUDIT-06 范围收敛：本审核入口仅服务于项目风险管理模块内的风险，不汇总冒烟等其他待审核事项（EXCL-01）。
	•	BR-PUSH-01 推送触发条件：仅由本功能的审核通过事件触发，非人工发起；一条风险只推送一次。
	•	BR-PUSH-02 推送内容最小集：必须包含风险唯一标识和风险核心业务字段，确保雪狼侧能建立关联和处理依据。
	•	BR-PUSH-03 状态联动：推送成功后本地风险保持"已审核/待同步"，等待 FUNC-10 回写更新处理进展；推送动作本身不改变风险的业务处理状态。
	•	BR-PUSH-04 协作边界：本系统只负责推送指令发出与回执记录；雪狼内部如何接收、分派、处理不在本 PRD 展开（EXCL-03）。
	•	BR-PUSH-05 失败语义：本期仅描述正常成功路径，失败后的补偿机制暂不设计（EXCL-02）。

编辑风险
功能编号：FUNC-04（变化类型：新增，用户分类表补充，BRD 未单独定义）
业务流程
	•	用户对处于允许编辑状态的风险进入详情页，点击"编辑"。
	•	系统按可编辑字段范围开放编辑，其余字段只读。
	•	用户修改指定字段后保存并提交，系统重新执行必填校验。
	•	校验通过后风险状态回到"待审核"，等待再次审核（若此前已审核通过并已推送雪狼，则按待核验规则决定是否重新走审核与推送联动，见业务规则 BR-EDIT-03）。
业务规则
	•	BR-EDIT-01 可编辑状态：默认仅"待审核"状态风险可编辑；是否放开"已审核/待同步"状态可编辑属待核验项（第五章待澄清①），未确认前按"仅待审核可编"实现，不扩大范围。
	•	BR-EDIT-02 可编辑字段范围：默认允许修改风险内容、分类、来源、级别、处理人、审核人及附件；核心标识类字段（风险唯一标识、创建人、创建时间）不可改。具体字段清单属待核验项（第五章待澄清②）。

雪狼风险数据实时同步
功能编号：FUNC-10（变化类型：新增）
业务流程
	•	监听来自"雪狼"平台的回写通道（具体形式为消息/接口/文件等，详见 VER-02）。
	•	解析回写报文，提取风险唯一标识、处理状态、应对措施、实际影响、更新时间、关闭标志、关闭时间、最终处理说明（如有）。
	•	以风险唯一标识匹配本地风险记录：匹配成功则更新本地风险的"处理状态""应对措施""实际影响""最近更新处理时间"等字段；若回写含关闭标志，同时更新本地风险状态为"已关闭（处理完成）"并记录关闭时间。
	•	幂等处理：同一风险同版本回写重复到达时不产生重复更新或冲突。
	•	更新完成后，风险列表、详情页、以及依赖该数据的关联页面（日报/首页/看板/报表，见 MOD-03~MOD-06）自然取到最新值。
业务规则
	•	BR-WRITE-01 回写字段固定集：处理状态、应对措施、实际影响为本功能的核心回写字段；关闭标志和关闭时间为关闭场景附加字段。
	•	BR-WRITE-02 匹配键：必须使用风险唯一标识进行本地匹配，禁止用风险内容等模糊字段匹配。
	•	BR-WRITE-03 幂等性：同一风险同一版本的回写多次到达，本地数据保持一致，不叠加、不覆盖为更旧版本。
	•	BR-WRITE-04 状态映射：雪狼侧的处理状态需映射到本系统的展示状态枚举；映射关系需在技术拆解阶段与雪狼侧对齐，PRD 层只要求"可识别且一致"。
	•	BR-WRITE-05 实时性：回写应为"实时"（业务要求），具体时效阈值未在 BRD 中确认，不作为硬指标写入；如后续需量化，应作为待核验事项提出。
	•	BR-WRITE-06 范围边界：本功能是回写的承接方，只定义字段和时机，不约束雪狼何时何因触发回写（EXCL-03）。

	•	定时任务按计划周期启动（调度频率、批量策略在 VER-03 中待核验，PRD 不预设具体值）。
	•	圈选范围：本地状态为"已关闭"（无论是审核拒绝还是处理完成）且最近一段时间内有过回写或推送记录的风险。
	•	向"雪狼"平台发起补同步请求，携带风险唯一标识列表，获取其最新关闭状态与最终处理信息。
	•	对账比对：两端一致则跳过；两端不一致则以雪狼端为准更新本地数据（处理状态、应对措施、实际影响、关闭时间、最终处理说明），并记录本次纠正。
	•	输出补同步执行报告：本轮扫描数量、纠正数量、异常数量，供运维跟踪。
业务规则
	•	BR-SYNC-01 目标对象：仅针对"已关闭"风险进行补同步；未关闭风险走 FUNC-10 实时回写主路径，不在本功能范围内。
	•	BR-SYNC-02 一致性方向：发现差异时以雪狼端为权威源更新本地，保证两端最终一致（GOAL-04）。
	•	BR-SYNC-03 不触发新业务：补同步只纠正数据，不改变风险的业务处理结论，不触发新的审核或推送。
	•	BR-SYNC-04 可观测性：每轮执行需有可查的运行报告和纠正明细，便于排查漏同步问题。
	•	BR-SYNC-05 与实时回写互补：本功能是 FUNC-10 的兜底补偿，二者并存，不因补同步而取消实时回写。

日报生成展示
功能编号：FUNC-16（变化类型：调整）
业务流程
	•	项目日报生成时（按既有调度机制），进入风险数据取数环节。
	•	"今天遇见的问题"板块：读取当天有变动的全量风险记录，包含当天新登记、当天发生审核动作（通过/拒绝）、当天收到雪狼回写更新处理进展、当天被关闭（无论审核拒绝还是处理完成）的风险——即含当天已关闭项在内的全量变动风险。
	•	"历史未解决的问题"板块：读取此前产生且当前仍未关闭的风险记录，排除当天已关闭的项。
	•	两个板块独立取数、独立渲染，互不覆盖、互不引用对方结果。
	•	日报其他板块逻辑不变，仅风险相关取数规则按本功能调整。
业务规则
	•	BR-DAILY-01 双口径分离："今天遇见的问题"和"历史未解决的问题"是两个相互独立的取数口径，不得合并或互相引用对方结果。
	•	BR-DAILY-02 "今天遇见的问题"口径 = 当天有变动的全量风险（含已关闭项）。变动包括新增、审核、回写更新、关闭等任何导致状态或内容变化的事件；当天已关闭的风险也计入本板块。
	•	BR-DAILY-03 "历史未解决的问题"口径 = 此前产生且当前仍未关闭的风险；当天新关闭的不计入此板块。
	•	BR-DAILY-04 数据源统一：两个板块的数据均来自本系统风险主数据 + 雪狼回写/补同步后的最新值，不允许从其他来源拼装。
	•	BR-DAILY-05 范围收敛：本功能只调整项目日报中风险相关的取数规则，不改变日报其他板块（非风险类问题、进度等）的逻辑。

7. 系统非功能性约束
本章集中描述适用于一体化测试平台（SYS_NEBULA）本次"项目风险管理闭环建设"的共性性能、安全、数据一致性、可用性与审计要求。每条约束标注稳定编号和适用范围（对应第六章功能编号 FUNC-01～FUNC-18）。仅记录 BRD、第三章承接范围或已确认业务事实能支撑的约束；未核验的具体数值（如响应时长阈值、并发量、可用率百分比、调度频率等）不在本 PRD 中编造，统一列入待核验事项或在技术拆解阶段确认。权限判定、重复申请/编辑处理等可观察业务行为仍归相应功能的业务规则（见 FUNC-09 等），不因涉及安全或幂等而全部归入本章。
