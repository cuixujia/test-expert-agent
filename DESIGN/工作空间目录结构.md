# AI生成测试用例工作空间目录结构
/home/instance/workspace/<userId>/<agentId>/
└── runtime_<projectId>/                      # 应用运行时根目录，所有会话共用，以雪狼项目为基准
    │
    ├── .opencode/                            # 运行时本地配置，用户自定义的智能体、工具、技能
    │   ├── agent/                            # Agent 定义、角色和权限
    │   ├── tool/                             # 自定义工具
    │   └── skills/                           # 技能、模板和引用资源
    │
    └── assets/                               # 创建工作空间时默认创建
        └── <prdId>/                          # 需求目录，同需求会话共享
            ├── <产品需求文档>                  # 【文件软链接】，需求文档
            └── <functionId>/                 # 业务功能目录
                ├── develop-docs/             # 开发设计文档（S7 必须输入）
                │   ├── fe-docs/              # 【目录软链接】，前端开发设计文档。以迭代粒度沉淀，通过业务功能所属迭代关系获取
                │   │   ├── tech1.md
                │   │   └── tech2.md
                │   └── be-docs/              # 【目录软链接】，后端开发设计文档。以迭代粒度沉淀，通过业务功能所属迭代关系获取
                │       ├── tech1.md
                │       └── tech2.md
                │
                ├── db-docs/                  # 【目录软链接】数据库资料，只读
                │   ├── tp-ddl.json           # 测试点库资料，以业务功能粒度召回（S3 可选输入：历史测试点）
                │   ├── tc-ddl.json           # 用例库资料，以业务功能粒度召回（S7 可选输入：历史测试用例）
                │   └── dict-ddl.json         # 数标库资料（S6 可选材料）
                │
                ├── domain-knowledge/         # 【目录软链接】自定义领域知识，以"业务功能"对应的"业务领域"沉淀领域知识并召回（S3/S7 可选输入）
                │   ├── domain1.md
                │   └── domain2.md
                │
                ├── code/                     # 【目录软链接】代码工程
                │   └── <源码文件及目录>
                │
                ├── output/                   # 【本地真实目录】用户确认采纳后的最终产物
                │   └── bf-tp-tc.json         # 测试用例集，业务功能-测试点-测试用例
                │
                └── session-log/              # 【本地真实目录】本功能流程会话过程资料（固定名；重新开始时归档为 session-log-归档-<日期>）
                    ├── input/                # 本次流程附带的输入资料（用户上传，只读）
                    ├── prd.txt               # 【本地真实文件】PRD 文本快照（S1 由原件转换生成），摘录逐字机验与漏锚扫描基准
                    ├── state.md              # 【本地真实文件】功能流程状态登记（PRD 指纹、门禁记录、派发会话等）
                    ├── scope.md              # 【本地真实文件】功能清单 + 锚点底册（S1 产出，全流程唯一溯源底册）
                    ├── prd-check.md          # 需求质检报告
                    ├── test-point.md         # 测试点清单
                    ├── tp-check.md           # 测试点质检报告
                    ├── design-check.md       # 详设质检报告
                    ├── test-case.md          # 测试用例清单
                    └── tc-check.md           # 测试用例质检报告

## 生成阶段输入约定

| 阶段 | 必须 | 可选（缺失或为空注明「未提供」，继续生成） |
|---|---|---|
| S3 测试点识别 | 产品需求文档 | domain-knowledge/、db-docs/tp-ddl.json（历史测试点）、session-log/input/（用户上传） |
| S7 用例生成 | develop-docs/（开发设计文档） | db-docs/tc-ddl.json（历史测试用例）、db-docs/dict-ddl.json（数标库，测试数据取值）、domain-knowledge/、session-log/input/（用户上传） |

> 必须材料缺失或为空：暂停请求补充（带风险推进须用户二次确认）；可选材料由平台按业务功能粒度召回，空即视为未提供。
> state.md、scope.md、prd.txt 为九阶段流程在会话目录内的功能文件（agent 读写落位）；其余软链接目录一律只读。
